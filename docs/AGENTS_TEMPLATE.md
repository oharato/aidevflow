# AGENTS.md (Project Rules & Guidelines)

本ドキュメントは、本リポジトリで作業するすべての AI エージェント（Google Antigravity CLI `agy`、Claude Code CLI `claude` 等）および人間の開発者が遵守すべき **プロジェクト固有の非機能要件・アーキテクチャ標準・コーディング規約** をまとめた正本です。
作業開始時は必ず本ドキュメントを最優先で確認し、ここに記載された制約を満たす設計・実装を行ってください。

---

## 1. ネットワーク & LAN アクセス (LAN Access & Binding)
- **バインド設定**:
  - バックエンド（FastAPI, Express, Go等）およびフロントエンド開発サーバー（Vite, Next.js等）は、必ず `0.0.0.0` でバインド起動すること（`127.0.0.1` や `localhost` に限定しない）。
  - 同一LAN内の別マシンやモバイル実機からブラウザでアクセス・検証できるように設定する。
- **フロントエンド Proxy (Vite / Next.js)**:
  - フロントエンドからバックエンドAPIを呼び出す際は、ブラウザの同一オリジン制約やLANアクセス時の CORS/IP 不整合を防ぐため、開発サーバーの Proxy 機能（例: `vite.config.ts` の `server.proxy`）を経由させること。
  - フロントエンドコード内でハードコードされた `http://localhost:8000` や特定IPを直接 fetch せず、相対パス（`/api/...`）を使用すること。

---

## 2. インフラ & Docker 運用規約 (Infrastructure & Docker)
- **ボリューム永続化 & パーミッション**:
  - PostgreSQL / MySQL / DuckDB 等のデータディレクトリやログディレクトリをホストにバインドマウントする場合、ホスト側のパーミッションエラー（Permission Denied）を防ぐため、適切なユーザーID（例: `user: "1000:1000"`）または名前付きボリュームを使用すること。
- **Docker Compose 構成**:
  - サービス名、ポートマッピング、環境変数（`.env`）の分離を徹底すること。
  - 開発者が `docker compose up -d --build` の一発で全スタックが起動・疎通する状態を維持すること。
  - コンテナ停止コマンド（`docker compose down`）や再起動手順を README に明記すること。

---

## 3. 共通アーキテクチャ & 外部サービス連携 (Architecture & Services)
- **LLM / 外部AIサービス接続**:
  - ローカル Ollama や外部 API（OpenAI, Anthropic 等）への接続は、リポジトリ内に用意された共通クライアント（例: `OpenAILikeLLMClient`）に一本化すること。
  - 各モジュールで独自に HTTP リクエストや SDK をインスタンス化して車輪の再発明を行わないこと。
  - 開発環境での接続先（例: `OLLAMA_BASE_URL=http://192.168.242.39:11434`）は環境変数経由で注入可能にすること。
- **DB スキーマ管理 & マイグレーション**:
  - マイグレーションツールはプロジェクト選定ツール（例: **Atlas 宣言的マイグレーション**）に一本化すること。
  - `schema.sql` やスキーマ定義ファイルを唯一の正（Single Source of Truth）とし、手動DDLスクリプトとの重複管理を行わないこと。
- **クローラー & 外部データ収集**:
  - `robots.txt` に完全準拠し、`DomainRateLimiter` によるアクセス間隔制御（最低1.5秒待機等）を徹底すること。
  - キューテーブルによる排他制御（`FOR UPDATE SKIP LOCKED`）を用い、デッドロックフリーな並行処理を実現すること。

---

## 4. 品質・テスト & エラーハンドリング (Quality & Error Handling)
- **検索・提案の0件時挙動 & ハルシネーション防止**:
  - 検索結果やマッチング結果が0件の場合、架空の企業名やデータを捏造（ハルシネーション）せず、明示的に「該当する情報は見つかりませんでした」と返却・表示すること。
  - フロントエンドには空状態（Empty State）のUIを実装すること。
- **文末途切れ・トークン溢れ対策**:
  - LLM の最大出力トークン数（`max_tokens`）による文末途切れを防ぐため、適切なトークン上限設定とストリーミングまたは要約処理を設計すること。
- **外部API・ライブテストの安全設計**:
  - 外部サービス（有償API、検索API、LLM等）のライブテストは、APIキーが未設定の場合はエラー終了させず、安全にスキップ（`pytest.mark.skipif` や Vitest の条件スキップ）すること。
  - 動作確認に必要な検証用シードデータ（実在法人番号、テスト用レコード）を用意すること。

---

## 5. 言語・ランタイム & バージョン固定 (Runtimes & Versions)
- **mise によるバージョン管理**:
  - プログラミング言語ランタイム（Node.js, Python, Go等）やツールのバージョンは `.mise.toml`（または `.tool-versions`）に明記し、固定すること。
- **パッケージ・ライブラリのバージョン固定**:
  - 新規パッケージ導入時は `@latest` や `@next` ではなく、具体的な最新安定版バージョン（リリース7日以上経過）を固定すること。
  - サポート終了（EOL）ライブラリや非推奨パッケージを使用しないこと。
- **TypeScript & Lint 規約**:
  - `tsconfig.json` では `strict: true` を基本とし、型エラー（any の乱用等）を放置しないこと。
