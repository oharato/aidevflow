# トラブルシューティング & エスカレーション仕様書

本ドキュメントでは、`aidevflow` の自己防衛機構（無限ループ防止、クォータ枯渇検知、プロセス多重起動防止）およびトラブル発生時の復帰手順について解説します。

---

## 1. 差し戻し無限ループ防止 (`MAX_REJECTION_COUNT`)

### 仕組み
レビューエージェント（Spec-Reviewer や Code-Reviewer）と作成エージェント（Spec-Writer や Developer）の間で修正と差し戻しが何度も繰り返されると、API コストや時間が浪費されます。

- **カウント追跡**: チケットごとの連続差し戻し回数をメモリ上で追跡。
- **上限到達**: 設定値（`.env` の `MAX_REJECTION_COUNT`、デフォルト: `3` 回）に達すると、ステータスを **「確認待ち」**（件名プレフィックスモードでは `[確認待ち]` かつ「未対応」）に変更。
- **Backlog 報告**: 差し戻し理由と現在の論点を整理したコメントを自動投稿し、自律パイプラインを安全に一時停止します。
- **リセット条件**: いずれかのレビューで承認（LGTM）されるか、人間が確認後にチケットを「処理中」に戻すとカウンターがゼロにリセットされます。

### 復帰手順
1. Backlog チケットのコメント欄で指摘内容や差分を確認。
2. コメントで方針や仕様を回答・指示。
3. ステータスを **「処理中」** に変更することで、最新指示を最優先コンテキストとして自律再開します。

---

## 2. AI からの人間確認要請 (`【人間への確認依頼】`)

### 仕組み
仕様の重大な矛盾、複数の設計選択肢（トレードオフ）、外部システム連携の未定義仕様など、AIエージェント単独で判断できない問題に直面した場合：

- エージェントはプロンプトの指示に従い、`【人間への確認依頼】` または `CONFIRM_HUMAN` タグを付けて論点を出力します。
- デーモンはこのタグを検知すると、差し戻し回数に関わらず即座にステータスを **「確認待ち」** に移行して一時停止します。

### 復帰手順
1. チケットコメントに提示された質問・選択肢を確認。
2. 人間が決定事項をコメントに投稿。
3. ステータスを **「処理中」** に戻します。

## 3. LLM クォータ上限（Quota Reached）時の安全停止 & 自動回復

### 仕組み
エージェント CLI（`agy` や `claude`）が LLM のクォータ制限（`Individual quota reached. Please upgrade your subscription...` や `429 Rate Limit` 等）や異常終了（終了コード != 0）に達した場合：

- **ローカルクォータロック (`.aidevflow.quota.lock`) の自動作成**:
  - エラー文からリセット予定時間（例: `Resets in 2h21m6s`）をパースし、ローカルにロックファイルを作成します。
- **Backlog ポーリングの完全休止**:
  - クォータ制限中は Backlog へのチケット監視 API 呼び出しを休止し、無駄な API 消費や他チケットの巻き込みエラーを防止します。
- **自動回復プローブ & 自動再開 (Auto-Resume)**:
  - リセット予定時刻が到来すると、自動的に超軽量プローブ（`agy -p "ping"` 等）を実行して回復を確認します。
  - 回復が確認され次第、ロックを自動解除し、中断していたチケットのステータスを更新して自動で自律処理を再開します（人間側の操作は不要です）。

### 復帰手順

- **【全自動復帰 (推奨・デフォルト)】**:
  - 特段の操作は不要です。コメントに記載されたリセット予定時刻が到来すると、デーモンが自動的にクォータ回復を検知してチケットを自律再開します。
- **【手動即時復帰 (プランアップグレードや別アカウントへの切替時)】**:
  1. ローカルのクォータロックファイルを削除します：
     ```bash
     rm .aidevflow.quota.lock
     ```
  2. 必要に応じて Backlog チケットのステータスを **「処理中」** に変更します。デーモンが即座に通常ポーリングを再開し、作業を再開します。

## 4. プロセス二重起動防止ロック (`.aidevflow.lock`)

### 仕組み
複数ターミナルでの重複起動や、バックグラウンド常駐と手動起動の重複による Git worktree の破損・ステータス上書きを防ぐため、厳格なプロセスロックを導入しています。

- **ロックファイル**: プロジェクトルートに `.aidevflow.lock` を作成（PID、起動日時、コマンドを記録）。
- **多重起動の即時ブロック**: 既に稼働中のプロセスがある場合、エラーメッセージを表示して即座に終了します。
- **Stale ロックの自動回収**: OS再起動や `kill -9` 等でロックファイルが残骸として放置された場合、OS の PID 生死確認を行い、プロセスが存在しない場合は自動回収して安全に起動します。

### ロック解除・確認コマンド
```bash
# 現在の稼働状況を確認
pnpm run status

# 稼働中プロセスの安全停止
pnpm run stop
```

## 5. 日常のトラブルシューティングコマンド

| 目的 | コマンド | 説明 |
| :--- | :--- | :--- |
| **稼働状態の確認** | `pnpm run status` | 実行中 PID、起動日時、コマンドを表示 |
| **安全停止** | `pnpm run stop` | 実行中タスクの完了を待機してプロセスを停止 |
| **リアルタイムログ監視** | `pnpm run logs` | JSONL ログをカラー表示でリアルタイム監視 |
| **手動ロック解放** | `node -e "import('./dist/daemon/lock.js').then(m => new m.ProcessLock('.aidevflow.lock').release())"` | クラッシュ時の緊急ロック解除 |
