# aidevflow: Backlog-driven AI Agent Pipeline Daemon

Backlog のチケット状態に応じて、人間の開発フローに沿った 5 つの専門 AI エージェント（**Antigravity CLI: `agy`**）を自律リレーさせ、**複数リポジトリの修正から GitHub プルリクエスト（PR）作成までを完全自動化** する TypeScript 常駐デーモンです。

参考: [食べログ技術ブログ - 対話型をやめて1度の指示でPRができる。人間の開発フローに沿って5つの役割をリレーするAIエージェントパイプラインの設計](https://tech-blog.tabelog.com/entry/autonomous-ai-agent-pipeline-cost-verification_55)

---

## ⚡ 5分でわかるクイックスタート

### 1. 準備
```bash
# 依存関係のインストール
pnpm install

# 設定ファイルの作成
cp .env.example .env
# .env を開き、BACKLOG_API_KEY や BACKLOG_PROJECT_KEY などを設定
```

### 2. デーモンの起動
```bash
# 画面でリアルタイムログを見ながら実行（動作確認向け）
pnpm start

# または、ターミナルを閉じても稼働し続けるバックグラウンド起動（通常運用向け）
pnpm run start:bg
```

## 📖 利用者ガイド（日常の使い方）

### ステップ 1: Backlog でチケットを起票する

課題の「詳細」に対象リポジトリ（単数または複数）と要件を記載します：

```markdown
リポジトリ:
- git@github.com:my-org/frontend.git
- git@github.com:my-org/backend.git

【要件】
ユーザー一覧APIを実装し、UI側のテーブルコンポーネントに結合してください。
```

> [!TIP]
> **ドラフト保護**: チケット作成直後のステータスは「未対応」のため、AI はまだ起動しません。下書きがすべて完了するまで安全に編集できます。

---

### ステップ 2: ステータスを「処理中」にして AI を開始する

準備ができたら、Backlog チケットのステータスを **「処理中」**（カスタム状態使用時は「詳細設計中」）に変更します。
デーモンが自動検知し、5役のエージェントが自律的にリレーを開始します：

```
[詳細設計中] (Architect)   : 要件から詳細設計書を作成
     ↓
[設計レビュー中] (Tech-Lead): 設計書を客観レビュー（不備があれば差し戻し）
     ↓
[実装中] (Developer)       : コード実装、単体テスト、GitHub PR 自動作成
     ↓
[技術レビュー中] (Code-Reviewer): 型・規約・セキュリティ・依存性の技術レビュー
     ↓
[要件レビュー中] (QA)      : 元のチケット要件を満たしているか最終受入レビュー
     ↓
[要件レビュー完了] (処理済み): 人間による PR レビュー待ち（完了コメント自動投稿）
```

---

### ステップ 3: 人間による PR レビュー & 完了 / 修正

全工程が完了すると、チケットのステータスが **「処理済み」**（件名: `[要件レビュー完了]`）になり、Backlog に **PRリンクと手元での動作確認コマンド** が投稿されます。

#### パターン A: 内容に問題がなく完了する場合（マージ）
1. GitHub 上でプルリクエストをマージします。
2. Backlog チケットのステータスを **「完了」** に変更してクローズします。

#### パターン B: 指摘・修正がある場合（AIに修正させたい場合）
1. **Backlog チケットのコメント欄** に修正指示を記入します（例: `「エラーハンドリングにフォールバック処理を追加してください」`、`「PR #1 のコメント通り修正して」`）。
2. チケットのステータスを **「処理中」** に戻します。
3. デーモンが自動的に `developer`（実装）を起動し、既存の作業ツリーで修正して **既存 PR に追記 push** します。その後、技術レビュー・要件レビューを経て再度「処理済み」として報告されます。

## 🎯 用途に合わせた 3 つの実行モード

`aidevflow` は、タスクの重さに応じてパイプラインを自動最適化します：

| モード | 発動方法 | パイプラインの流れ | 用途・メリット |
| :--- | :--- | :--- | :--- |
| **通常モード** | 通常のチケット作成 | `architect` → `tech-lead` → `developer` → `code-reviewer` → `qa` (5段階) | 新機能開発や大規模改修向け |
| ⚡ **Fast モード** | 件名に `[fast]` を付与<br>または本文に `mode: fast` | `developer` → `code-reviewer` (2段階で即PR作成・完了) | 既知のバグ修正・文言修正・軽微な変更用。<br>**クォータ消費を約 60% 削減** |
| 🔍 **調査モード** | 件名に `[調査]` を付与<br>または種別・カテゴリーを「調査」 | `architect` → `tech-lead` (2段階で調査ドキュメント作成・完了) | 技術選定・比較検証・アーキテクチャ設計用。<br>コード実装をスキップして完了 |

## 🛠️ 日常の運用コマンド一覧

| 操作 | コマンド | 説明 |
| :--- | :--- | :--- |
| **フォアグラウンド起動** | `pnpm start` | コンソールに標準出力をリアルタイム表示して起動（`Ctrl + C` で停止） |
| **バックグラウンド起動** | `pnpm run start:bg` | ターミナルを閉じても常駐稼働するバックグラウンド起動 |
| **稼働ステータス確認** | `pnpm run status` | 実行中 PID、起動日時、コマンドラインを確認 |
| **リアルタイムログ監視** | `pnpm run logs` | ログファイル（`logs/aidevflow.jsonl`）をカラー表示で `tail -f` 監視 |
| **安全停止** | `pnpm run stop` | 実行中タスクの完了を待機してから安全に終了（Graceful Shutdown） |
| **モック起動 (テスト用)** | `AGENT_RUNNER=mock pnpm start` | LLMを呼ばずトークン消費ゼロで Backlog 連携や PR 作成の流れをシミュレート |
| **テスト実行** | `pnpm test` | Vitest による単体・結合テストの実行 |
